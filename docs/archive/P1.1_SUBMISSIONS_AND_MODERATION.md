# P1.1 — submissions and moderation

## Routes

- `POST /api/submit`: requires a valid Supabase access token. Canonicalizes the Instagram URL, validates the HTTPS destination URL, checks for an existing published/pending match, and creates a pending submission.
- `GET /api/admin/submissions?status=pending&limit=25`: requires an active administrator allowlist entry.
- `PATCH /api/admin/submissions`: requires an active administrator allowlist entry and accepts `{ "submissionId": "...", "decision": "approve" | "reject", "reviewNote": "..." }`.

## Schema contract

These routes expect the P0 schema to provide:

- `posts.canonical_url` (unique), `posts.id`
- `submissions.id`, `post_id`, `submitted_by`, `resource_url`, `normalized_resource_url`, `resource_type`, `description`, `status`, `created_at`
- `resources.id`, `post_id`, `resource_url`, `resource_type`, `description`, `status`, `created_at`
- Submission states `pending`, `approved`, `rejected`; published resource state `published`

If the actual schema uses different names or enum labels, create a deliberate migration and update the route contract together. Do not deploy mismatched code.

## Security and correctness notes

- The client cannot choose a contributor ID, post ID, publication status, or admin role.
- Pending submissions never appear in the public resolver.
- Admin routes use server-verified Supabase Auth and a database-backed allowlist.
- The resource URL validator does not fetch destinations. It is not proof of ownership, trustworthiness, or redistribution permission.
- The current approval flow uses multiple database calls. It attempts cleanup if the submission update fails, but this is not a true transaction. Before production, replace approval/rejection with a single PostgreSQL RPC that locks the submission, records an append-only review/audit entry, creates the resource and updates status atomically.
- `reviewNote` is accepted for future UI compatibility but is not persisted yet. Do not show a UI implying that notes are saved.
- No automated link verification or reward crediting is performed in this checkpoint.

## Manual smoke test

1. An unauthenticated submission request returns 401.
2. A contributor cannot call the admin queue or review endpoint successfully.
3. An authenticated contributor can submit a valid URL and receives `pending`.
4. An identical pending or published resource returns a duplicate response rather than another row.
5. The public resolver does not return the pending submission.
6. An authorized admin can reject a pending submission.
7. An authorized admin can approve a pending submission, after which the resolver returns only the published resource.
8. Re-reviewing an approved/rejected submission returns 409.
9. Invalid Instagram URLs, non-HTTPS destinations, malformed JSON, and oversized descriptions are rejected.
10. Inspect logs and responses to ensure they do not reveal service-role keys, private evidence, or database internals.

These checks are a test plan, not a claim that the routes have been executed. Run them against a separate development Supabase project before using real users.
