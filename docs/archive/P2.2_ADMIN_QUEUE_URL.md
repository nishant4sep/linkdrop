# LinkDrop P2.2 — Canonical URLs in the admin API

## Change

The admin submissions API now enriches each submission with `canonical_url`, looked up from `public.posts`. The lookup is deliberately separate from the submission query, so it does not rely on an assumed PostgREST relationship name.

The queue response includes:

- `submissions`: moderation records, each with `canonical_url` or `null` if the related post is missing.
- `pagination.limit`: applied limit.
- `pagination.count`: number of returned records.

The UI must render `submission.canonical_url` as a link using `target="_blank"` and `rel="noopener noreferrer"`, and should show a clear fallback if the URL is null. Do not construct an Instagram URL from an internal database UUID.

## Before running

1. Confirm `requireAdmin(request)` returns `{ ok: true, user }` on success and `{ ok: false, status, error }` on failure.
2. Confirm `requestOriginAllowed(request)` exists and returns a boolean.
3. Confirm the moderation RPC argument names and decision values match migration `0003_atomic_moderation_and_rate_limits.sql`.
4. Confirm `submissions` and `posts` contain the columns selected in this route.
5. Confirm the admin UI sends `submissionId`, `decision` (`approve` or `reject`), and optional `reviewNote` to PATCH.
6. Run the project's TypeScript check and production build, then test with a contributor, an active admin, and a disabled admin.

## Security notes

- Admin authorization is checked server-side on both methods.
- The browser must never receive the service-role key.
- PATCH checks request origin and delegates the actual decision to the atomic database RPC.
- Error responses avoid returning raw database error messages.
- This endpoint does not fetch arbitrary resource URLs; URL verification workers need their own SSRF protections.
