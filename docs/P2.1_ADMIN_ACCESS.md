# LinkDrop P2.1 — Admin access foundation

## Purpose

Create the explicit database allowlist required by server-side moderation authorization. This migration does not make anyone an administrator automatically.

## Before applying

1. Back up the Supabase project.
2. Confirm migration `0003_atomic_moderation_and_rate_limits.sql` and the current schema are available.
3. Confirm the app's `requireAdmin()` helper checks the authenticated Supabase user on the server and verifies a matching `public.admin_users` row with `disabled_at IS NULL`.
4. Confirm admin mutations use the server-side moderation RPC and never trust a role, user ID, or approval decision supplied by the browser without server authorization.
5. Apply to a development project first. Do not blindly run against a populated or differently structured database.

## Grant the first administrator

Only after a trusted account has signed up and its email/account identity has been independently confirmed, run this manually in the Supabase SQL editor as the project owner. Replace the UUID with the verified user's actual `auth.users.id`.

```sql
insert into public.admin_users (user_id, notes)
values ('REPLACE-WITH-VERIFIED-AUTH-USER-UUID', 'Initial project administrator');
```

The placeholder above is documentation only; do not execute it unchanged. Never expose service-role credentials in a browser or commit them to source control.

## Disable an administrator

```sql
update public.admin_users
set disabled_at = now()
where user_id = 'REPLACE-WITH-VERIFIED-AUTH-USER-UUID';
```

The table intentionally has no browser-facing RLS policies. Admin access should be granted or revoked through trusted database-owner operations or a separately reviewed, audited server-side process.

## Required integration checks

- A signed-out request to every admin API returns an authorization error.
- A normal authenticated contributor cannot read or mutate the moderation queue through admin endpoints.
- A disabled administrator cannot access admin endpoints, even if their session remains valid.
- A valid administrator can list the queue and approve/reject a submission.
- Every moderation mutation is recorded by the database's moderation review/audit design.
- The admin queue displays the canonical Instagram post URL from `public.posts`, not just its internal UUID.
- The public resolver returns only approved/published resources and never pending submissions.
- Repeated requests and concurrent moderation attempts do not publish duplicate resources or double-award rewards.

## Compatibility warning

This migration creates only `public.admin_users`. It does not repair mismatched enum values, column names, moderation RPC signatures, or assumptions in `src/lib/server.ts`. Before deployment, compare migration `0003` and the API routes against the actual schema. In particular, verify the submission/resource status values and the exact columns selected by the admin endpoint.
